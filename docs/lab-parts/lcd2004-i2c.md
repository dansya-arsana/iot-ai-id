# LCD2004-I2C

Protocol: `i2c`. A 20 x 4 character LCD (HD44780 controller) behind a PCF8574 I2C backpack, used with Wire.

- Device (simulation): `apps/web/src/lab/sim/devices/lcd2004-i2c.ts`
- Part (3D): `apps/web/src/lab/scene/parts/lcd2004-i2c.ts`
- Test: `tests/lab-part-lcd2004-i2c.test.ts` (backpack and controller tests plus the real sketch `tests/fixtures/sketches/lcd2004-rows.ino`)
- Pins: GND, VCC, SDA, SCL (breadboard legs, the order printed on the backpack)

## What is simulated

- PCF8574 port byte: P0 RS, P1 RW, P2 E, P3 backlight, P4..P7 D4..D7. The controller latches on the FALLING edge of E, 4-bit mode after the 0x3, 0x3, 0x3, 0x2 wake-up.
- Address: PCF8574 backpacks answer at 0x20..0x27, PCF8574A ones at 0x38..0x3F; the popover offers all sixteen (0x27 and 0x3F are the ones sold). The I2C bus matches the current value at every START.
- Memory: a 20 x 4 panel is a two-line (N=1) controller with 40 characters per line. Row 1 = 0x00..0x13, row 2 = 0x40..0x53, row 3 = 0x14..0x27, row 4 = 0x54..0x67. Text that runs past column 20 continues on row 3 (or 4); a display shift moves all four windows and wraps within the 40-character line.
- Commands: clear, home, entry mode (I/D, S), display control (D, C, B), cursor and display shift, function set (N), CGRAM address (8 custom glyphs shown as codes 0..7), DDRAM address, data write, and DDRAM/CGRAM/address-counter reads (high nibble first). With N=0 only row 1 is driven.
- Busy flag: always ready (no execution time). Contrast is a visual factor (trim pot), not a signal.

## Provenance

Own work from the public HD44780 and PCF8574 datasheet behaviour. The 5 x 7 glyph table is the public-domain column font used by the other lab LCD. Dimensions (98 x 60 mm board, 76 x 25 mm viewing area) from the generic 2004 module outline; no vendor art, photos or logos.
