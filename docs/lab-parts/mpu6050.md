# MPU6050

Protocol: `i2c`

- Device (simulation): `apps/web/src/lab/sim/devices/mpu6050.ts`
- Part (3D): `apps/web/src/lab/scene/parts/mpu6050.ts`
- Test: `tests/lab-part-mpu6050.test.ts`
- Pins: VCC, GND, SCL, SDA, XDA, XCL, AD0, INT (GY-521 header order)

## Behaviour

I2C address 0x68 (AD0 to GND or open) or 0x69 (AD0 to 5V/3V3); WHO_AM_I (0x75) always reads 0x68. Powers up asleep (PWR_MGMT_1 = 0x40, data registers read 0) until the sketch clears it; DEVICE_RESET (0x80) restores that state. Registers modelled: SMPLRT_DIV 0x19, CONFIG 0x1A (DLPF: 8 kHz gyro rate when off, 1 kHz when on), GYRO_CONFIG 0x1B and ACCEL_CONFIG 0x1C (full scale, LSB/g 16384..2048, LSB/dps 131..16.4), INT_PIN_CFG 0x37 (active level, latch, read-clear), INT_ENABLE 0x38, INT_STATUS 0x3A, data 0x3B..0x48 (big-endian int16: accel XYZ, temperature, gyro XYZ; auto-increment burst reads), USER_CTRL 0x6A, PWR_MGMT_1/2 0x6B/0x6C. Temperature word: degC = raw/340 + 36.53.

Popover: roll (back edge up), pitch (right edge down), spin about the vertical (dps), chip temperature. Accel is gravity in the sensor frame (ax = -sin p, ay = sin r cos p, az = cos r cos p; the usual atan2 formulas give the angles back). Gyro is the exact body angular rate of the tilt motion the popover causes (plus the spin); full scale clips at +-32767. The 3D board tilts with the same signs. The tilt eases to its target with an 80 ms time constant (a hand turning the board) so a slider jump is not an impossible instant rotation.

Data ready: the INT pin pulses 50 us at each sample period (or holds until INT_STATUS is read when latched; active low when INT_PIN_CFG bit 7 is set). A polling sketch sees a fresh sample at every transaction start once the period has elapsed.

Not modelled (registers stored only or absent): FIFO, I2C master (XDA/XCL), motion detection, standby bits, self-test, offset registers, open-drain INT.
