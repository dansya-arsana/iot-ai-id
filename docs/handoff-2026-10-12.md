## Invitation-only areas, members and presentation mode

On iot.ai.id, anonymous visitors see "By invitation" instead of Products, Builders, PhysicalBench, Arena, Build, Sites, Design, the `/id` leaderboard and the Learn start button. They get Request access (to `/partner`), Sign in (`/masuk`) and WhatsApp. Invited members (clients, partners, schools) sign in with a username and password, set up from a one-time invite code, and unlock areas by grant: `products`, `bench`, `arena`, `builders`, plus `installer`, which only adds the desktop download button to `/profile`. Build, Sites and Learn's start button need the owner-only cloud `/api`, so members are told the workspace runs in the desktop app.

- Manage members in the backoffice at Members (`#bo-members`, owner and sales): add (the code is shown once), edit grants, disable or enable, reset the invite, read the history. Downloads are logged per member.
- Set `OPS_INSTALLER_URL` (https only) in the ops env file (`/opt/iot-ai-id/secrets/ops.env`) and recreate the ops container. Until it is set, `/ops/v1/member/installer` answers 503 "not configured".
- Members sign-in sets a readable `aiot_member_hint` cookie so anonymous page loads make no `/ops/v1/member/me` request (school NAT addresses would otherwise exhaust the per-IP zone). Re-enabling a never-activated member issues a fresh invite, shown once.
- The nginx member locations (login and activate on `iot_portal_auth`, the rest on `iot_portal`) are in `deploy/nginx.conf`, but production needs an idempotent patch added to `deploy-ops.sh` (that script is git-excluded and was not touched): see the block in the report.
- A staff member signed in at admin.iot.ai.id still opens iot.ai.id with everything unlocked and a pill to switch back to the public view. Build and Sites there offer "Open in workspace" on the admin host.
- To re-open a page for everyone, remove it from `GATES` in `apps/web/src/preview.tsx` and from the list in `scripts/build-seo.ts`.
- Honest limit: the GitHub release assets remain public until they are moved to private storage. The gate controls our links only. The public host no longer links the releases at all.
- E2E aliases: `iot.admin.localhost:8891` (public; also serves `/ops/v1/member/*`) and `admin.localhost:8891` (admin). The Members UI e2e drives the backoffice on plain localhost, because the admin alias never serves `/api`.

## Known limits

- Payouts are recorded, not executed: the transfer is manual, then it is marked paid with a reference.
- No email or SSO sign-in and no password reset by email. An owner resets the invite instead.
- Lockout and wrong credentials show the same message by design.
- An owner can reset another owner's invite. That is within the owner's authority, but it is worth knowing.
- Public site rule: no fake partners, schools or numbers. Show empty states honestly.
